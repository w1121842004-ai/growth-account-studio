# ADR-011: 新功能经 Feature Flag 灰度发布

## Status
Proposed — 待 team-lead 确认后转为 Accepted。

## Background
MVP 上线后新生成能力（如新模型、新排版模板）需降低全量风险。

## Decision
采用轻量 Feature Flag（见 db/schema.sql 的 feature_flags 表 + openapi.yaml 的 /features）：
- 开关表含 `key / enabled / rollout{user_ids, percentage}`。
- 后端中间件 `checkFeatureFlag(key, userId)` 决定功能可见性；前端从 `/api/v1/features` 拉取当前用户开关。
- 灰度阶段：内测(团队)→5%→50%→100%，各阶段观察错误率/性能/反馈后再扩量。

## Consequences
- 正面：新功能可安全小流量验证，失败即时回滚。
- 负面：需在前后端各加少量 Flag 读取逻辑；MVP 初期 Flag 少，开销可忽略。
- 关联：openapi.yaml 的 /features、db/schema.sql 的 feature_flags。
