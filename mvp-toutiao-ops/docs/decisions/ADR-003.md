# ADR-003: node-cron 仅负责定时采集，生成与发布由人触发

## Status
Proposed — 待 team-lead 确认后转为 Accepted。

## Background
需周期性拉取热榜。是否把「生成」「发布」也放进定时任务？

## Decision
**node-cron 仅定时触发热榜采集（零 LLM 成本、幂等写入 hotlist_entries）**。内容生成、人工审核、导出均由真人在 Web 界面点击触发，不做任何自动化流水线。
理由：
- 采集是确定性、无费用、可幂等的任务，适合定时。
- 生成消耗 LLM 额度且需人工审核把关（半自动产品定位）；自动跑生成既烧钱又违反「草稿人工审核后发布」需求。
- 自动发布踩微信合规红线（见 ADR-007），不可自动化。

## Consequences
- 正面：cron 进程轻量、失败不影响主服务；成本可控。
- 负面：cron worker 需独立于 Next.js 进程运行（Lighthouse 容器内用 Docker Compose 起第二个 service 或同容器后台进程）；需保证采集失败可重试、不重复写入（唯一约束 source+title+date）。
- 关联：ADR-001（单体不含长驻 cron）、ADR-008（采集源）、ADR-010（部署）。
