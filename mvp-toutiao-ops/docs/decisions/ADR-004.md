# ADR-004: 统一排版采用 Block AST 中间表示 + 双渲染器

## Status
**Accepted（技术强制）** — 推翻原 PRD「一套内联 HTML 兼容双平台」前提（blocking B-1）。

## Background
原假设：产出一份内联 style HTML，同时粘贴进微信与头条编辑器即可。
实测结论（Phase 1 联网验证）：
- 微信编辑器：强制全内联 style、剥离 class/id、支持 `<section>` 嵌套、支持 gradient/box-shadow/border。
- 头条编辑器：ProseMirror 内核，按 schema 白名单解析；inline style 全量剥离；`<section>` 不在白名单；`<br>` 段落内被吞；`<pre>` 可保留；层级靠 Unicode 符号（◆▶【】）。
→ 一套内联 HTML 无法同时满足两者，原前提不成立。

## Decision
引入 **Block AST**（语义化中间表示，见 schemas/block-ast.schema.json），由 Tiptap 3 编辑产出，再由两个独立渲染器消费：
- 微信渲染器：输出全内联 style 的 HTML（`<section>` 嵌套、渐变/阴影可用）。
- 头条渲染器：输出零 CSS 的语义化 HTML，层级用 Unicode 符号（◆ 一级、▶ 二级、【】标题），不使用被剥离的样式。
单一事实源（Block AST）保证双平台内容一致，差异只在渲染策略。

## Consequences
- 正面：彻底解决双平台不兼容；编辑一次、双端预览一致；合规样式可控。
- 负面：需实现两个渲染器 + 一个 AST 校验器；Tiptap 产出需映射为 Block AST（写适配器）。
- 关联：block-ast.schema.json（契约）、openapi.yaml 的 /export/render（双 target）、ADR-007。
