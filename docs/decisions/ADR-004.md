# ADR-004: AI SDK 6 + 混元 Hy3 分档热切换

## Status
Accepted — Spec §4/§5/ADR-004 锁定（2026-08-16）。

## Background
F5 要求模型热切换（通义/智谱/混元抽象，先接 1 个 + 熔断）。三家均提供 OpenAI 兼容端点，是否自研底座？

## Decision
**Vercel AI SDK 6.x** 统一协议层；适配层读 `model_configs` 表（base_url/api_key/model/role/enabled），热切换不改代码。分档：
- 主力：腾讯混元 **Hunyuan Hy3**（`tokenhub.tencentmaas.com/v1`，TokenHub OpenAI 兼容端点），中文创作性价比 + Prompt Cache 命中 0.25。
- 省钱档：混元 **hunyuan-lite**（免费），选题批量打分等低难度任务。
- 备选：智谱 **GLM-4.7-Flash**（免费）/ 通义 **Qwen Plus**（OpenAI 兼容），主模型不可用时熔断切换。
**熔断**：每 provider 连续失败计数，达阈值开路、半开探测恢复（AC-08）。**Prompt Cache 禁写日期**：稳定系统提示作为可缓存前缀，当前日期等易变值放入用户消息，避免缓存失效（混元缓存 0.25 收益最大化）。

## Consequences
- 正面：一套调用覆盖多厂商；热切换零改码；流式由 AI SDK 原生支持；成本按 provider 入 usages 表。
- 负面：依赖三家端点持续兼容 OpenAI 协议；密钥应用层加密存储。
- 关联：db/schema.ts model_configs、usages；openapi /models；impl/model-adapter.md。

## Amendment 2026-08-16：provider 包版本锚定纠错

Spec §4 原锚定 `@ai-sdk/openai@4.0.42`（"latest"），实测与 `ai@6.x` **不兼容**，`tsc` 报：

```
src/lib/ai/adapter.ts(45,3): error TS2322:
  Type 'LanguageModelV4' is not assignable to type 'LanguageModel'.
    Types of property 'specificationVersion' are incompatible.
      Type '"v4"' is not assignable to type '"v2"'.
```

根因是 AI SDK 的 provider spec 版本与顶层包版本**不同步演进**，取 latest 会踩错配：

| 顶层 `ai` | 依赖的 `@ai-sdk/provider` | 匹配的 `@ai-sdk/openai` |
|---|---|---|
| 6.0.256 | 3.0.15 | **3.0.97** |
| 7.0.66 | 4.0.7 | 4.0.42 |

**决定**：保持 Spec 锚定的 AI SDK 6 大版本不变，将 provider 包**精确锁定**为 `@ai-sdk/openai@3.0.97`（其依赖 `@ai-sdk/provider@3.0.15` + `@ai-sdk/provider-utils@4.0.46`，与 `ai@6.0.256` 完全一致）。不升 `ai@7`——避开一次无收益的 major 迁移。

**约束**：`@ai-sdk/openai` 在 package.json 中必须写**精确版本**（不带 `^`）。加 caret 会在 `npm install` 时漂到 4.x 并再次撞 spec 不兼容。升级 `ai` 主版本时必须同步查表更换 provider 包。

## Amendment 2026-08-17：混元端点地址纠错 + 省钱档模型修正

实测 `api.hunyuan.cloud.tencent.com/v1`（旧站端点）对 TokenHub 签发的 API Key 返回 401 invalid_api_key；混元 OpenAI 兼容接口的**现行正确端点为 `tokenhub.tencentmaas.com/v1`**（TokenHub 新站，`.env` / registry 兜底 / Spec 已同步）。原省钱档模型 `hunyuan-a13b` 在 TokenHub 无对应开通，实际采用免费档 `hunyuan-lite`（打分链）。
